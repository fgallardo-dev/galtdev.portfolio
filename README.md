## About

Personal portfolio with an editorial look — Bodoni Moda headlines, floating tech cubes, and Kobi the koala. Every piece is built with three non-negotiables:

> **Semantics first · Accessibility always · Maximum performance**

No UI frameworks, no client-side bloat: static HTML generated by Astro, a few lines of vanilla JavaScript where interaction genuinely needs it.

## Features

- 🌍 **Real i18n routes** — `/` (Spanish) and `/en/` (English) with `hreflang`, canonical URLs, and full Open Graph metadata
- 🧭 **Semantic, accessible navigation** — real links, `aria-current` state, mobile menu driven by `aria-expanded` + CSS `:has()`
- 🎨 **Responsive hero** — fluid type with `clamp()`, a shared *stage* container so the koala and its pedestal scale in lockstep
- 🔍 **Project filter** — native `<select>` filtering cards through `data-*` attributes, with an `aria-live` empty state
- 🗂️ **Data-driven content** — projects live in a schema-validated Markdown collection and technologies in a typed data file, not in markup

## Tech stack

| Choice | Why |
|--------|-----|
| [Astro 7](https://astro.build) | Static output, zero JS by default — performance is the goal |
| TypeScript (strict) | Typed data models and honest interfaces |
| Tailwind CSS v4 | Design tokens via `@theme` in CSS, no config file |
| Vanilla JS | Two small scripts: mobile menu & project filter — nothing more |

## Structure

```
portfolioGaltdev/
├── public/            # favicon, robots.txt (sitemap-index.xml is generated at build)
└── src/
    ├── assets/        # optimized images: logo, Kobi, projects/<slug>/
    ├── components/    # Nav · Hero · Projects · ProjectDetail · Footer
    ├── content/       # projects collection: one Markdown per project in es/ and en/
    ├── content.config.ts   # collection schema: frontmatter validation
    ├── data/          # typed sources: techs.ts
    ├── i18n/          # ES/EN translations
    ├── layouts/       # base layout: SEO, hreflang, fonts
    ├── lib/           # project helpers: slugs, URLs, language parity, page wiring
    ├── pages/         # / (es) and /en/ routes, incl. proyectos/[slug] · en/projects/[slug]
    └── styles/        # Tailwind v4 theme tokens
```

## Adding a project

1. Copy a template from `src/content/projects/es/` and `src/content/projects/en/` — same file name in both folders (it becomes the URL slug).
2. Put the images in `src/assets/projects/<slug>/`. Use **1640x1025 (16:10)**: the detail hero requests widths up to 1640px and `astro:assets` never upscales, so a smaller source is served soft on high-density screens.
3. Fill in the frontmatter and the body in each language; the comments in the template explain every field. `cover` is the informative image (it carries the alt text and shows on mobile); `hover` is decorative and hidden from assistive tech, so keep the product shot as the cover.
4. Set `draft: false` in both files. The build fails if a published project is missing in one language.

## Getting started

```bash
cd portfolioGaltdev
npm install
npm run dev      # → http://localhost:4321
```

| Script | Action |
|--------|--------|
| `npm run dev` | Dev server with hot reload |
| `npm run build` | Production build to `dist/` |
| `npm run preview` | Serve the production build locally |
